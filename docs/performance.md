# 高速化と計測

2026-11-23、ローカルmacOSで測定。動画・ディスク・CPU・FFmpegビルドにより結果は変わる。

## 実施内容

- 未表示のタブではプレビュー生成などを開始しない。最初の表示後はタブを離れてもマウントを維持し、進行中の解析を継続する。
- ビットレートグラフ、ラウドネス、総合チェック、AI会話、コマンド画面のコードを必要になるまで読み込まない。
- 基本解析、ビットレート、フレーム分布、ラウドネス、整合性、タイムスタンプ、ブラック・無音、異常フレームの同一条件の実行中リクエストを共有する。進捗は途中参加者にも通知する。完了・失敗後の明示的な再実行は省略しない。
- サムネイルを2件並列で生成し、デコーダーを各2スレッド、フィルターを各1スレッドに制限して過剰なスレッド生成を避ける。画像の一覧順序は時刻順、進捗は実際の完了枚数を維持する。
- サムネイルのRust側キャッシュは最大48件・合計24MiB。パス、更新日時、サイズ、ツールパス、抽出時刻、画像幅をキーにし、同じパスのファイル更新を再確認する。容量を超える画像は保存しない。
- フレーム選択の待ち時間を180msから80msへ短縮し、各ピッカーのデコーダーは同時に1件までにする。待機中に古くなったシーク位置は生成を開始しない。
- ffprobeのパケット出力をJSONからキー付きcompact形式へ変更する。入力を行単位で処理して数値パケットへ直接変換し、文字列フィールドを持つ中間配列を作らない。Bフレームの順序とGOP集計の結果を結合テストで比較する。
- ハッシュ計算の進捗通知を最大毎秒10回に制限する。ハッシュ計算自体の読み取り・精度は変えず、開始・終了は即時通知する。
- メタデータ表示をメモ化し、生JSONの整形はそのタブを初めて開いた時に行う。

## 計測値

テスト動画: H.264、1280×720、30fps、20秒、Bフレームあり。各条件3回の中央値。サムネイル12枚、幅320px。キャッシュを利用せず外部プロセスの実行を比較。

| 項目 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 12枚のサムネイル生成 | 687.27ms | 367.64ms |
| ffprobeのパケット出力取得 | 41.24ms | 39.10ms |
| ffprobeパケット出力サイズ | 90,026 bytes | 34,800 bytes |
| 初期JSのメインチャンク（圧縮前） | 417.14KB | 約320KB |
| 同チャンク（gzip） | 137.46KB | 約99KB |

サムネイルは約46%短縮。前後で12枚すべてのJPEGバイト一致を検証。パケット出力サイズは約61%削減。パケット取得時間にはffprobe起動時間も含むため、短い動画では時間差は小さい。JSの数値はメインチャンクのサイズであり、全機能使用時の総転送量やアプリ起動時間ではない。

再現コマンド:

```sh
node scripts/benchmark-media.mjs
```

合成動画を一時ディレクトリに作成し、計測・出力一致の検証後に削除する。`ffmpeg` / `ffprobe`、または`FFMPEG_PATH` / `FFPROBE_PATH`が必要。
