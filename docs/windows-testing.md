# Windows実機テスト

2026-11-23、v1.1.0のリファクタリング・高速化後のソースをSSHでWindows x64機へ転送して検証。
専用の作業フォルダで検証。

環境: Node.js 24.19.0、npm 11.17.0、Rust 1.98.0、Visual Studio 2022 Build Tools。
FFmpeg/ffprobeはWindows CIと同じBtbNの静的ビルド（20261122版）を使用。
署名用秘密鍵・AI APIキーは転送していない。

| 確認項目 | 結果 |
| --- | --- |
| `npm ci` | 成功 |
| フロントエンド自動テスト | 39件すべて成功 |
| `npm run build` | 成功 |
| Rust自動テスト | 22件すべて成功 |
| `cargo clippy --all-targets -- -D warnings` | 成功 |
| メディア性能測定と出力一致 | 成功 |
| Windows release exe・NSISセットアップ生成 | 成功 |
| 通常デスクトップでの起動 | セッション1、タイトル`ffScope`、ウィンドウあり、応答あり、WebView2子プロセスあり |

Rustの結合テストにはMP4/Bフレームのタイムスタンプ・ビットレート集計、異常フレーム検出、ラウドネス測定、サムネイル更新が含まれる。

## 性能測定

720p、30fps、20秒の合成H.264動画、各条件3回の中央値。

| 項目 | 変更前相当 | 変更後相当 |
| --- | ---: | ---: |
| サムネイル12枚 | 596.22ms | 249.45ms |
| パケット出力取得 | 39.25ms | 38.36ms |
| パケット出力サイズ | 93,630 bytes | 35,400 bytes |

前後のJPEGバイト列とパケットの内容一致を確認。異なるマシン・FFmpegビルドなので、macOSとの数値の単純比較はしない。

## 検出・修正した問題

- Rust 1.98のClippyで検出された認証ヘッダーの冗長な参照を修正。認証動作は変えていない。
- 性能測定スクリプトでWindowsのCRLFを正しく分割するよう修正。アプリ本体のRustパーサーはWindowsの実ファイルを用いたテストでも成功。
- SSHのセッション0から直接起動すると、WebView2の親ウィンドウ作成が`0x80070578`で失敗した。ログイン中のユーザーの通常デスクトップで一時タスクを使って起動し、正常動作を確認。起動したアプリは終了し、一時タスクは削除済み。
